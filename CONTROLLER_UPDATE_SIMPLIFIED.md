# Controller Update Guide (Simplified - Integer PKs)

## Important Change: No More UUIDs!

All new tables now use **auto-incrementing integer primary keys** instead of string UUIDs. This simplifies controller code significantly.

---


## 4. AppointmentController.php (NEW)

```php
<?php

namespace App\Http\Controllers;

use App\Models\Appointment;
use Illuminate\Http\Request;

class AppointmentController extends Controller
{
    public function store(Request $request)
    {
        $request->validate([
            'patient_id' => 'required|exists:patients,patient_id',
            'scheduled_date' => 'required|date',
        ]);

        $appointment = Appointment::create([
            // appointment_id auto-generated ✅
            'patient_id' => $request->patient_id,
            'staff_id' => $request->staff_id ?? auth()->id(),
            'scheduled_date' => $request->scheduled_date,
            'status' => 'scheduled',
        ]);

        return response()->json($appointment, 201);
    }
}
```

## 5. VaccineInventoryController.php (NEW)

```php
<?php

namespace App\Http\Controllers;

use App\Models\VaccineInventory;
use App\Models\InventoryTransaction;
use Illuminate\Http\Request;

class VaccineInventoryController extends Controller
{
    public function store(Request $request)
    {
        $request->validate([
            'vaccine_type' => 'required|string',
            'batch_number' => 'required|string',
            'quantity' => 'required|integer|min:1',
            'expiration_date' => 'required|date',
        ]);

        $inventory = VaccineInventory::create([
            // inventory_id auto-generated ✅
            'clinic_id' => auth()->user()->clinic_id,
            'vaccine_type' => $request->vaccine_type,
            'batch_number' => $request->batch_number,
            'current_quantity' => $request->quantity,
            'expiration_date' => $request->expiration_date,
            'status' => 'active',
        ]);

        // Log transaction
        InventoryTransaction::create([
            // transaction_id auto-generated ✅
            'inventory_id' => $inventory->inventory_id,
            'staff_id' => auth()->id(),
            'transaction_type' => 'received',
            'quantity' => $request->quantity,
            'transaction_date' => now(),
            'remarks' => 'Initial stock',
        ]);

        return response()->json($inventory, 201);
    }

    public function deduct(Request $request, $id)
    {
        $inventory = VaccineInventory::findOrFail($id);

        $request->validate([
            'quantity' => 'required|integer|min:1|max:' . $inventory->current_quantity,
            'reference_id' => 'nullable|string', // treatment_id
        ]);

        // Deduct stock
        $inventory->decrement('current_quantity', $request->quantity);

        // Log transaction
        InventoryTransaction::create([
            'inventory_id' => $inventory->inventory_id,
            'staff_id' => auth()->id(),
            'transaction_type' => 'used',
            'quantity' => -$request->quantity, // Negative for deduction
            'transaction_date' => now(),
            'reference_id' => $request->reference_id,
            'remarks' => $request->remarks ?? 'Vaccine administered',
        ]);

        return response()->json($inventory->fresh(), 200);
    }
}
```

## Key Takeaways

### ✅ Simpler Code:
- No UUID generation needed
- No `Illuminate\Support\Str` imports
- Laravel handles ID generation automatically

### ✅ Model Changes:
- `PatientQueue` → `Queue`
- `VaccinationSchedule` → `TreatmentRecord`
- `bite_incident_id` → `bite_id`

### ✅ No Fillable Changes Needed:
- Don't include primary key in fillable array
- Laravel auto-generates IDs

### ✅ Relationships Still Work:
```php
$patient->queues; // Works with integer IDs
$patient->treatmentRecords; // Works with integer IDs
$biteCase->location; // Works with integer IDs
```
