## Field aliases and dependencies to resolve

| Current editor key/example | Related live/API representation | Design implication |
| --- | --- | --- |
| `sex` | Registration request uses `gender` | Explicit alias is required |
| `emergency_contact_phone` | Registration request uses `emergency_contact_number` | Share the existing payload mapping |
| `spouse_name` | Displayed only when civil status is married | Required must be conditional |
| `has_membership`, membership-specific details | Membership groups and conditional selections | Parent/child visibility and validation must agree |
| `date_of_consultation` | Treatment request uses `consultation_date` | Do not equate UI labels with request keys |
| `body_part_affected`, `body_part_affected_text` | Treatment card request uses `body_part_exposed`, `body_part_detail` | Explicit form-specific translation is needed |
| `animal_type_other` | Treatment card request uses `animal_type_others` | Existing aliases must be reconciled |
| `past_history_bite`, `pep_completed` | Treatment card request uses `past_bite_history`, `past_pep_completed` | Similar names do not establish equivalent allowed values |
| `icd_code` | Treatment card request uses `icd10_code` | Map deliberately |
| `last_name`, `first_name`, `sex`, derived clinical fields | Required or system-controlled in live flows | Classify lockable/configurable status before exposing rules |

These are examples from [patientService.ts](../../frontend/src/features/patients/services/patientService.ts), [StorePatientRequest.php](../../backend/app/Http/Requests/Clinical/StorePatientRequest.php), [StoreTreatmentRecordRequest.php](../../backend/app/Http/Requests/Clinical/StoreTreatmentRecordRequest.php), and [StoreTagoloanTreatmentCardRequest.php](../../backend/app/Http/Requests/Clinical/StoreTagoloanTreatmentCardRequest.php). This alias list is a design input, not a completed per-field consumer specification.

## Legacy six-key configuration

Setup and the default seeder create `bite_location`, `exposure_category`, `animal_status`, `philhealth_info`, `fourps_info`, and `wound_washing`. Only `exposure_category` and `animal_status` overlap the current 41-key contract; `animal_status` also has a different default (Optional in the six-key seed versus Required in the current service). Preserve explicit valid choices when normalizing; do not infer a safe migration solely from similarly named fields.

See the [audit](admin_module_configuration_audit.md) for verified failure behavior and the [implementation plan](implementation_plan.md) for remediation.
