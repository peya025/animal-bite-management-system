## Goal and scope

Make emailed staff and patient portal invitations usable from any Wi-Fi network or mobile data through the deployed Vercel frontend and Railway backend. The user's computer must not need to be running.

## Troubleshooting guide

| Symptom | First checks |
| --- | --- |
| Email still contains a local address | Railway URL variables, cached configuration, worker restart if applicable, and whether the invitation was sent from the local system |
| Staff link returns a hosting 404 | Vercel domain, deployment availability, and SPA rewrite |
| Staff page opens but API calls fail | Frontend build's API URL, backend availability, and exact CORS origin |
| Portal activation returns 404 | Link must point to Railway; verify the deployed Laravel route |
| Portal submission reports a session/CSRF error | HTTPS, session persistence, cookie configuration, and form submission origin |
| Token is invalid immediately | Correct database/environment, complete link/fragment, expiration, or a newer invitation replacing the old one |
| Email is not delivered | Production mail configuration and delivery logs; inspect workers only if the delivery path is queued |
